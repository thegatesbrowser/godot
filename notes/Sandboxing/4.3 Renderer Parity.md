# 4.3 Renderer Parity

How the `tg-4.3` renderer stands against `tg-4.5`, from the 2026-07 parity pass. `tg-4.3` is a legacy branch that produces the older renderer artifact only; the launcher is always built from `tg-4.5`. Verified against branch code, not assumptions.

## The key insight: broker-side fixes ride the launcher, not the renderer

Several Linux sandbox fixes live in code that runs only in the broker role — i.e. inside the launcher process. The launcher is always built from `tg-4.5` (`.gitmodules` pins `branch = tg-4.5`; `tg-4.3` never builds a launcher). So the current launcher already applies these to **every** renderer it spawns, 4.3 renderers included. `tg-4.3`'s own copy of that file lacking the fix is dead code in the renderer-only role it ships.

This is why most "4.3 is missing X" items are already handled in production.

## Ported in this pass (real 4.3-only code, on the `tg-4.3` branch)

- **Crash + seccomp-denial logger** — was entirely absent on 4.3; ported (crash logger + `[SECCOMP] denied syscall N` logging + the vendored libzmq `SIGSYS` patch). 4.3 renderers now leave a trace when they crash or hit a denied syscall. The libzmq patch must be **re-applied if libzmq is ever re-vendored on 4.3** — 4.3 has no `CLAUDE.md` to carry that warning, so it lives here.
- **Force-Vulkan safety net** — 4.3's renderer didn't pin the Vulkan driver, so a gate requesting Direct3D 12 could break the shared-texture pipeline (the 4.3 binaries really do have D3D12 compiled in). Ported (~5 lines), matching `tg-4.5`.
- **External-texture binding arg name** — cosmetic doctest-hygiene fix, taken along.

`tg-4.3` is a standalone branch with no cherry-pick partner (the `tg-4.5` → `tg-master` sync rule does not include it) — these are 4.3-only commits.

## Deferred — already handled, do NOT port (re-check on Linux if in doubt)

- **Open-file-limit raise** — broker-side (launcher). The launcher already raises it for every renderer it spawns, since 1.0.3. Was a real 4.3 crash historically, but fixed via the launcher, not a renderer rebuild. Re-check: force-open a 4.3 gate on Linux, confirm the renderer's open-file soft limit equals the hard limit.
- **XAUTHORITY passthrough + Linux shader-cache redirect** — broker-side (launcher), same reasoning. Re-check: launch a 4.3 gate on X11, confirm both are set/redirected and the renderer log shows no display-auth or shader-cache-permission errors.
- **Wayland keep-drawing-while-suspended** — 4.3 already has its **own** independent fix (it disables the suspend detector entirely under the renderer build), reached by a different route than `tg-4.5`'s always-draw override. Do NOT stack `tg-4.5`'s override on top. Re-check: cold-boot a heavy 4.3 gate on Wayland, confirm no suspend-timeout in the log and frames advance.

## Deployment-freshness caveat (not a code issue)

Even where the `tg-4.3` branch carries a fix, the server-hosted 4.3 renderer zip must have been rebuilt/reuploaded after the fix date for users to actually get it. Confirm the served 4.3 renderer downloads are current when validating.
